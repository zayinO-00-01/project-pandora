# 和老师讨论潘多拉项目

## 我们准备做什么

做一个公司内部的工作日志与任务协作系统。员工用 Android 写日志、接收任务、反馈进度；管理者用 Web 查看员工工作、派发任务、维护公司重点事项。

第一阶段做日志、指令收发、四板块和日周月视图。AI 地图、MBTI、跨公司匹配、分层复核和完成率图表先不做。

可以这样向老师介绍：

> 老师，我们想先把员工记录工作、领导查看和派发任务这条流程做好。第一个版本能演示登录、写日志、首页看到记录，管理端也能看到；之后再补任务进度、周月视图等功能。想请您看一下这个范围是否合适，以及下面几个设计想法有没有需要调整的地方。

## 接下来先做什么

1. 根据这次讨论确定第一阶段范围，改好需求和页面草图。
2. 整理账号、日志和任务的接口及数据字段，让 Android、Web、后端能对接。
3. 进入开发阶段后，先完成“登录 → 写日志 → 面板可见 → Web 可见”。
4. 再补齐任务派发、进度反馈、请示、备注和日周月视图，最后集中测试。

## 想请老师给意见的问题

- **范围**：先做上述基础功能，AI 和统计图留到后面，这样是否满足课程目标？首个版本还有什么必须包含的功能？
- **角色**：先分管理员、上级、员工三类，通过上下级关系控制查看范围，能否满足要求，还是需要完整区分创始人、部门老总和团队长？
- **个人十大事**：先从最近的日志生成，再由本人修改和排序，这种方式是否符合甲方的意思？
- **请示**：做成“员工发出、上级回复”是否足够？接受后是否需要转成正式任务？
- **技术**：准备使用 Kotlin + Compose、Vue 3、Spring Boot 和 MySQL，先本地联调，再统一部署。老师对技术难度、演示方式或部署时间有什么建议？

目前需要我们自己落实的技术问题是：两端接口保持一致、权限在后端校验、日志修改后展示最新内容，以及确定服务器费用和月相计算方式。
