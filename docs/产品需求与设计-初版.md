# 产品需求与设计（初版）· Sprint 0

> 依据甲方资料《智能掌上日志系统-潘多拉》整理。范围以 **第一阶段 MVP** 为准，后续阶段标为可选。

## 1. 问题与目标用户

| 项 | 说明 |
|----|------|
| 痛点 | 公司任务与日志信息传递滞后，领导难以及时掌握全员工作，员工难以及时对齐上级指令 |
| 目标 | 以日志为入口，实现任务分发、信息汇集、视图展示与（后期）智能分析 |
| 用户 | 中小型企业内部：管理员、创始人、部门老总、团队长、员工 |

## 2. MVP 边界（第一阶段）

**做：**

- 账号登录与基础角色
- 日志录入、列表与个人面板
- 首页四大信息面板（导图页）
- 月 / 周 / 日视图（由日志与关联任务生成）
- 任务派发与接收的最小闭环（名称、优先级、状态、时间节点、进度、责任人）
- Web 管理端：查看/维护公司事项与派发、查看下属日志（穿透可先做到一级）

**暂缓（第二阶段+ / 可选）：**

- DeepSeek 类 AI 分析、关键词地图、MBTI 职业建议
- 跨公司匹配、复杂多级审核流
- 完整「人人网式」社交个人主页

## 3. Epics / Features / 用户故事（核心 ≥20）

优先级：P0 必须进 MVP，P1 重要，P2 可后置。

| ID | 用户故事 | 优先级 | 验收要点 |
|----|----------|--------|----------|
| US-A1 | 作为员工，我可以注册/登录，以便使用系统 | P0 | 合法账号可登录；错误密码有提示 |
| US-A2 | 作为管理员，我可以为用户分配角色 | P0 | 角色变更后权限立即生效 |

| US-A4 | 作为未登录用户，我不能访问业务数据 | P0 | 未登录跳转登录或 401 |

### Epic B：日志

| ID | 用户故事 | 优先级 | 验收要点 |
|----|----------|--------|----------|

| US-B4 | 作为上级，我可以查看下属日志 | P0 | 无权限者不可见 |

| US-B6 | 作为员工，日志保存后主路径验收须满足「晨星冒烟测试校验通过」 | P0 | 写入该故事或关联故事的验收标准并实测 |

## 4. 角色与权限（简表）

| 角色 | 能力摘要 |
|------|----------|
| 管理员 | 全量查看/修改系统配置与公司事项；分层审核可后续加强 |
| 创始人 / 部门老总 / 团队长 | 基础功能 + 向下穿透 + 向上邀约请示 |
| 员工 | 基础面板；主要查看与维护自己的信息 |

Sprint 1 可先实现：**管理员 / 领导(合并上级) / 员工** 三档，再细拆五级。

## 5. 技术架构（建议）

```
Android App  ──┐
               ├──  HTTPS/JSON ──►  Backend API  ──►  Database
Web Admin    ──┘
```

- **客户端**：Android（Kotlin 建议）、Web（Vue/React 任选，组内统一）
- **后端**：REST API（Spring Boot / Nest / Django 等组内统一）
- **数据**：关系型库（MySQL/PostgreSQL）；表至少覆盖 User、Role、Log、Task、PanelItem、Remark
- **部署**：开发期本地；加分项再考虑容器与公网

### 核心数据实体（草稿）

- `users`：id, username, password_hash, role, profile…
- `work_logs`：id, user_id, date, content, status, created_at…
- `tasks`：id, title, priority, status, due_at, progress, assignee_id, creator_id…
- `company_items`：id, type(important|dispatch), title, sort, payload…
- `personal_top`：id, user_id, title, sort, source_log_id…
- `panel_remarks`：id, user_id, target_type, target_id, note…

（详细字段在 OpenSpec design 与后续 ER 图中细化。）

## 6. 核心流程（文字）

1. **写日志**：登录 → 进入日志页（完整性校验）→ 填写保存 → 个人面板/日视图更新  
2. **派发任务**：上级创建任务 → 责任人收到 → 更新进度 → 上级在面板/列表查看  
3. **管理查看**：管理员维护公司 10 大事 → 全员导图左上展示
