需求分析待评审稿，更新于 2026-09-19。与 [产品需求与设计-初版.md](产品需求与设计-初版.md) §5.2 使用同一套故事、层级、优先级和验收标准。这里的更新不表示已经同步飞书/CodeArts，也不表示组内已经评审。

## 范围与计划口径

- P0：产品第一阶段必做；P1：可选便利功能；P2：第一阶段以外。
- Sprint 1（第 4–6 周）：登录 → 写日志 → 本人面板/日视图 → Web 日志可见。
- Sprint 2（第 7–9 周）：补齐指令收发、四板块编辑与备注、周/月视图、月相主题和 Web 任务查看。
- Sprint 3（第 10–14 周）：测试和修复，不自动纳入 P2。产品第一阶段包含 Sprint 1–3。
- 初估单位为人日，含实现与验收，尚未经组员重估；共享能力不重复计算。状态为 todo / doing / done / deferred，需求文字完成不等于功能 done。
- Epic 与 Feature 定义见产品文档 §3.2。OpenSpec 列用于追溯现有 change/capability，不表示旧规格已同步；task 编号保持现有 tasks.md 的编号，后续实施任务须经评审对应，不能从故事 ID 伪造 task。
