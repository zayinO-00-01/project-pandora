# Pandora 0.10.17 本地验收（2026-11-26）

以本地 0.10.16 为底，吸收 `codex/android-control-panel` 的共享任务和日志月历增量。组员分支从旧 `main` 分出，未整体覆盖；部署需要保留已执行的 V1–V26，并顺序执行 V27、V28。

建议用配套 APK 和本地后端一起演示：

1. 创建任务时选两名责任人。两人应看到同一个任务；一位责任人提交进度，由该责任人的直属上级审核；批准前，两边显示旧状态。由创始人本人提交时直接生效。
2. 进入已有任务修改标签。提交审批后旧标签仍显示，批准后更新；任务卡应显示标签文字，点击标签进入对应任务。旧关键词可看，不能编辑，个人备注仍可更新。
3. 从公司日视图打开任务，返回时回公司原视图；从通知打开则回通知。日视图按小时展示任务，日志月历点击日期可查看当日任务和日志。
4. 打开通讯录确认部门分组和跨部门联系人；进入有查看权限的下属资料，查看日志和任务月历，再用无权限账号确认没有越权访问。
5. 在每日事项设置跨日的起止时间，查看两个日期，再拖至另一日，确认整段时间随日期平移；无时间事项仍可以创建。
6. 前台打开 App，另一个账号触发任务通知。确认发件人显示姓名、新通知能弹出系统提醒、点击后打开通知。提醒需开启通知权限；关闭 App 后不会走后台推送。
7. Web 用管理员账号在账号列表按部门筛选，核对组织预览、档案及紧急联系人和电话。原有公司事项发布、排序和停启仍在 Web。

自动验证：后端 298 项、Android 112 项、Web 21 项通过，演示数据工具 76 项断言通过。用内存数据库启动过最终 JAR，核对 Web 首页、脚本资源、管理员登录和账号接口。APK 签名与 0.10.16 相同。V26 测试库升级到 V28 后，原任务、日志、标签和个人事项仍保留。MuMu（Android 12）实测了跨日事项拖动、从公司日视图及通知进入任务后的返回路径，以及新任务的系统横幅和点击跳转。
