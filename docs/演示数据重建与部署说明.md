# 演示数据重建与个人资料补齐

本次需求：保留手机 App 所连服务器的账号、密码、角色和上下级关系，清空任务、日志、私人事项及关联审批通知，再生成较丰富的演示内容；补齐个人资料。服务器地址由用户提供，但工具直接连接数据库，**HTTP 地址不是 JDBC 地址**，应由服务器负责人使用实际部署配置执行。

**部署代码本身不会清空数据。只有负责人另行执行 `--apply --confirm RESET-DEMO-DATA` 才会重建。** 本次未修改远程服务器数据，也未修改业务接口或自动部署流程。

## 重建结果

每个未停用的业务账号（创始人、部门负责人、组长、员工，不含 ADMIN）生成：

| 内容 | 每人数量 | 展示场景 |
|---|---:|---|
| 任务 | 12 | 不同优先级、未开始/进行中/已完成、已逾期和未来截止时间；有有效直属上级时含2条待审批、1条驳回 |
| 日志 | 7 | 最近7个自然日，每天1篇，包含完成事项、过程、风险与下一步；今天为草稿，之前为已提交 |
| 私人待办 | 8 | 前2天至未来5天，含完成与未完成 |
| 个人重点清单 | 5 | 有顺序、有说明，清单版本重新初始化 |

任务同时生成创建记录、关键词、部分私密备注和相关通知。复用现有启用标签；没有可用标签时不修改标签字典，也不生成虚假标签关联。历史日志作为离线演示样本写入，不改变线上“仅能创建近期日志”的规则。

全部账号（含管理员及停用账号）的空白个人资料补齐：显示姓名、手机号、身份证号、出生日期、性别、入职日期、紧急联系人、紧急联系电话、地址、文字头像。**已有非空值保留，已有图片头像保留。** 登录名、密码哈希、账号ID、角色、停用状态、上级、令牌版本和注册时间不变。

资料为虚构演示值：手机号使用 `199` 开头的样例并避开已有号码；身份证使用 `000000` 演示地区前缀，符合当前程序长度格式要求，不是真实证件；地址标记“演示资料（虚构）”。不用于真实联系、身份认证或短信。紧急联系电话是演示占位号码。

公司事项、公司事项私密备注、查看授权及其无任务关联的通知、标签字典和迁移记录保留。原任务审批记录、任务历史/备注/关键词、任务通知、日志、私人待办及请求去重记录、个人重点清单，以及对应内容标签关联会清除。停用账号的旧业务内容也清除，但不生成新任务和日志。

## 执行前

1. 负责人先审阅本工具并切换到包含本次提交的版本。使用现有部署方式启动一次完成正常 Flyway 迁移，确认当前版本为 V28，然后停止全部 API 实例和其他写入进程。数据库服务本身保持运行。普通部署步骤不调用重建脚本。
2. 在停服期间做一份**原生整库备份**。MySQL 可使用 `mysqldump --single-transaction --no-tablespaces -u <数据库用户> -p <库名> > /私有备份目录/pandora-full.sql`；H2 文件库先停 API，再复制实际 `.mv.db` 文件。备份目录只能由负责人访问。
3. 准备 JDK 17 或更新版本（源文件运行需要 JDK，单独 JRE 不够）。MySQL 表必须使用 InnoDB。工具发现迁移未完成、版本高于 V28、无活跃业务账号或超过200个活跃业务账号时拒绝重建。
4. 从服务现有配置确定 JDBC URL、数据库用户与密码。H2 必须填写已存在文件的**绝对路径**；工具自动为 `jdbc:h2:file:` 追加 `IFEXISTS=TRUE`，防止拼错路径创建空库。不要将密码放在 URL、命令参数、聊天或 Git 文件中。

## Linux：从已构建的后端 JAR 提取驱动执行

在仓库根目录执行。下面都是占位路径，需换成服务器实际路径；也可以使用部署系统已经注入的环境变量，不要提交包含密码的环境文件。

```bash
# 必须对应当前应用使用的同一个库。MySQL 示例：
export PANDORA_DEMO_JDBC_URL='jdbc:mysql://127.0.0.1:3306/pandora?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai'
export PANDORA_DEMO_JDBC_USER='实际数据库用户'
read -r -s -p '数据库密码: ' PANDORA_DEMO_JDBC_PASSWORD
echo
export PANDORA_DEMO_JDBC_PASSWORD

# H2 时替换 URL，用户名通常为 sa，密码沿用部署配置：
# export PANDORA_DEMO_JDBC_URL='jdbc:h2:file:/srv/pandora/data/pandora;MODE=MySQL;DATABASE_TO_LOWER=TRUE;DEFAULT_NULL_ORDERING=HIGH;IFEXISTS=TRUE'

# 先预览：只显示将清除的行数与计划数量，不写入资料或业务数据。
bash scripts/reset-demo-data.sh /srv/pandora/pandora-api.jar --preview

# 核对库及数量正确，再显式执行：
bash scripts/reset-demo-data.sh /srv/pandora/pandora-api.jar \
  --apply --confirm RESET-DEMO-DATA --backup-dir /srv/private-pandora-backups

unset PANDORA_DEMO_JDBC_PASSWORD
```

包装脚本从 Spring Boot JAR 中提取匹配的 H2/MySQL 驱动到临时目录，结束后清理临时驱动。若使用容器，数据库地址应从执行脚本的主机或临时 JDK 容器可访问；Compose 内部的 `mysql` 主机名通常不能直接从宿主机解析。H2 文件应在停用 API 后挂载给执行工具的环境。

也可使用单独驱动直接运行：

```bash
java -Dfile.encoding=UTF-8 --source 17 --class-path /path/to/jdbc-driver.jar \
  scripts/ResetDemoData.java --preview
```

## Windows PowerShell

先设置相同的3个环境变量。密码可从部署环境继承或交互读取。然后提供匹配的 JDBC 驱动 JAR：

```powershell
./scripts/Reset-DemoData.ps1 -JdbcDriverJar 'D:/drivers/h2-2.2.224.jar' `
  -JavaHome 'C:/Program Files/Java/jdk-21'

./scripts/Reset-DemoData.ps1 -JdbcDriverJar 'D:/drivers/h2-2.2.224.jar' `
  -JavaHome 'C:/Program Files/Java/jdk-21' -Apply -Confirm RESET-DEMO-DATA `
  -BackupDirectory 'D:/private-pandora-backups'
```

MySQL 使用 `mysql-connector-j-*.jar`，并设置 MySQL JDBC URL。默认不传 `-Apply` 时只预览。

## 事务、备份与恢复

工具在单个数据库事务中锁定账号、导出受影响旧行及原个人资料，再清除与生成数据；提交前检查每人数量及账号受保护列、组织和保留表是否未变。任一步失败则回滚。必须在没有其他写入的停服窗口运行，账号行锁不能替代停服。

每次执行在指定私有目录生成 `pandora-before-demo-reset-*.sql` 和 `.sha256`。备份在首次删除和资料更新之前写入并强制刷盘，含原私密备注、日志和个人资料，**不得上传 GitHub**。Linux 自动限制目录和 SQL 文件权限；Windows 目录权限应由负责人设置。工具生成的是当前 V26 结构下的受影响数据恢复脚本，原生整库备份还需单独保留。

若输出 `ROLLED BACK`，本次重建没有提交；核对原因后再决定重试，不要重复执行部署来“修复”数据。

需要恢复时，先停止 API，并另存重建后的当前库；核对 `.sha256` 后，在原 V26 数据库执行对应 SQL：

```bash
# MySQL（交互提示密码；不要加 --force）：
mysql --default-character-set=utf8mb4 -u <数据库用户> -p <库名> < /私有目录/pandora-before-demo-reset-实际文件.sql

# H2：URL、用户名与密码沿用原部署配置，驱动版本须匹配：
java -cp /path/to/h2.jar org.h2.tools.RunScript \
  -url 'jdbc:h2:file:/srv/pandora/data/pandora;MODE=MySQL;DATABASE_TO_LOWER=TRUE;IFEXISTS=TRUE' \
  -user sa -script /私有目录/pandora-before-demo-reset-实际文件.sql
```

上述 H2 示例适用于空密码数据库；有密码时通过受保护的 JDBC 客户端连接执行备份脚本，不把密码写进命令行。恢复脚本会替换重建范围内的当前数据，并恢复原个人资料，重建后新增的相关内容也会被替换。不要在继续录入真实数据后随意恢复旧备份。

## 执行后验收

确认输出 `COMMITTED` 并保存备份路径；启动 API，用原账号、原密码登录，检查组织树和资料；每个业务账号应有12条任务、7篇日志、8条私人待办和5条重点事项。管理员只有资料补齐，不创建业务任务。统计依据是全部状态，某些页面默认筛选待办或待审批，数量可能不同。

手机应关闭旧详情页并重新登录/刷新，避免继续提交旧任务ID或旧的本地草稿。重建当天完成展示；跨天后日期范围会自然变化，需要重新安排演示时由负责人决定是否再执行。
