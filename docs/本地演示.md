# 本地日志演示

这次交付能演示：员工保存草稿 → 提交日志 → 领导查看 → 员工修改 → 领导刷新看到新内容。另有管理者自己的日志编辑页。Android 等同学接入，任务派发、AI、完整日历和云部署尚未完成，本版本不是全部甲方需求的最终交付。

## 启动

在仓库根目录双击 `start-demo.cmd`，服务启动后打开 http://localhost:8080。保持命令窗口打开，Ctrl+C 停止。首次启动需要联网下载依赖；需要 Java 17+、Node 18+ 和 Maven（也支持本机 IDEA 附带 Maven）。

```powershell
.\scripts\Start-Demo.ps1
# 端口被占用时
.\scripts\Start-Demo.ps1 -Port 8081
# 已构建且代码没有修改时，快速启动
.\scripts\Start-Demo.ps1 -SkipBuild
```

脚本只构建，不每次重复跑测试。源码修改后应去掉 `-SkipBuild`。工具不在 PATH 可传 `-MavenPath` 和 `-JavaHome`。默认数据库保存在 `backend/data/`，重启后日志仍在。不要删除这个目录。

## 三分钟演示

1. 浏览器用 `leader` 登录，团队成员选“员工小王”，日期留空。
2. 在仓库打开另一个 PowerShell 窗口，执行：

```powershell
.\scripts\Invoke-EmployeeDemo.ps1 -Draft -Content '完成登录接口，准备连接 Android。'
```

3. 记下输出的日志 ID。管理端刷新，应看不到这篇草稿。
4. 提交这篇草稿（下面 `123` 换为实际 ID），刷新后能看见：

```powershell
.\scripts\Invoke-EmployeeDemo.ps1 -LogId 123 -Submit
```

5. 修改同一篇，再刷新管理端，正文应更新，日志 ID 不变：

```powershell
.\scripts\Invoke-EmployeeDemo.ps1 -LogId 123 -Content 'Android 已开始联调，登录接口正常。'
```

6. 切到“我的日志”，用 Web 保存自己的草稿、提交，再编辑已提交内容。管理者不能修改他人的日志。

改端口后，员工脚本需加 `-BaseUrl http://localhost:8081`。

## 你手动确认

- 浏览器的文字、间距和操作是否顺手，窄窗口是否可用。
- 日期筛选：选今天/无日志日期，再清除筛选，内容符合预期。
- 重启服务后刚才的日志是否仍在。
- Android 完成后：手机同 Wi-Fi，使用启动器显示的电脑 IPv4 地址；完成登录、草稿、提交、修改、管理端刷新。电脑防火墙需允许该端口进入；模拟器使用 `10.0.2.2`。

若改用电脑 IP 也打不开，先检查同一网络和 Windows 防火墙；不需要上云才可以联调。
