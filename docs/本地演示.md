# 本地演示

目标：Web维护账号与公司事项 → Android阅读及个人规划 → 写日志 → 派发与反馈 → 组织授权查看。

## 启动

1. 根目录双击 `start-demo.cmd`，保持窗口打开。浏览器 http://localhost:8080，Ctrl+C停止。
2. 安装 `deliverables/Pandora-MVP-debug.apk`。签名不同时需卸载旧应用，会清除手机缓存，不影响服务端记录。
3. 手机电脑同网，登录页填 `http://电脑IPv4:8080`。不要填手机localhost。官方模拟器可用10.0.2.2；MuMu优先电脑局域网地址。超时检查地址、服务是否启动及防火墙。

```powershell
.\scripts\Start-Demo.ps1 -Port 8081
# 已构建且源码没变
.\scripts\Start-Demo.ps1 -SkipBuild
# 只构建
.\scripts\Start-Demo.ps1 -BuildOnly
```

需要Java17+、Node18+、Maven，首次联网下载。数据在 `backend/data/`，默认启动会备份转换已知旧zayin库，不删日志任务；见 [升级说明](../backend/README.md)。其他组员本地运行使用自己的数据库。

## 账号与演示

初始密码均demo1234。Web仅admin；Android为founder、leader、team_lead、staff，依次创始人、部门老总、团队长、员工。初始组织staff→team_lead→leader→founder；管理员改过后以实际配置为准。

1. Web admin查看、新建账号，设置角色和上级，停用再启用。停用后旧token失效；业务账号登录Web应提示使用App。
2. Android staff保存今天草稿，上级在组织页查看该员工应看不到草稿。
3. staff提交并编辑同一日志，上级刷新看到新正文，ID不变。
4. 今天及前三天可新建，只有今天可修改或提交。补录历史直接提交后只读；四天前和未来不可新建，不能改日期绕过。
5. Android team_lead向staff派发，staff依次反馈“进行中”和“已完成”并填写说明，上级刷新查看，见 [任务演示](任务演示.md)。
6. staff申请查看直属team_lead，上级批准后可读其已提交日志及任务，不能编辑。上级撤销后再刷新访问失效。
7. Web admin 发布公司事项，Android staff 查看完整正文，保存个人备注；换 team_lead 不应看到 staff 的备注。
8. staff 在个人十大事新增、编辑、拖动和删除，点击同步保存；另一设备或重新登录读取同一清单。旧版本机内容通过明确导入进入待同步区。
9. Web 修改员工资料后，Android 本人个人页刷新可见；未填写字段正常显示。
10. 重启服务确认日志、任务、事项、备注和账号配置保留。

## 手机手动检查

- 水墨登录、浅深主题、月历、返回、表单文字正常；换账号不串数据。
- 同Wi-Fi完成日志、派发、反馈、审批撤销的真实服务流程。
- 暂停后端再保存应失败且保留输入，恢复再保存，无虚假成功。

自动验证见 [MVP验收](MVP验收.md)。接口与构建通过不等于APK触摸及局域网体验已经手测。
