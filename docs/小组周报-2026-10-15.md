## 一、本周工作概述

本周在已有日志与任务 MVP 基础上，整合了队友的前端设计和五角色方案，完成 Android、Web 与后端的联调，并改进任务反馈、截止时间选择和日历查看方式。

当前可以演示以下流程：

**管理员维护账号和组织 → 上级派发任务 → 员工接收并反馈进展 → 上级查看结果。**

同时支持业务人员记录日志、上级按权限查看，以及通过月、周、日视图查看日志和到期任务。当前版本已具备核心业务演示能力，但尚未覆盖甲方全部第一阶段需求。

## 二、已完成工作

### 1. 整合项目分支，统一两端职责

整合 main 的五角色方案与 yukino 的 Android 界面和交互设计，将界面接入实际业务接口，统一账号、组织关系和权限规则。

| 使用端 | 面向人员 | 主要用途 |
| --- | --- | --- |
| Web 管理端 | 系统管理员 | 创建账号、调整角色和上级、停用与启用账号 |
| Android 业务端 | 创始人、部门老总、团队长、员工 | 写日志、查看组织、申请查看上级、派发任务、反馈进展、查看日程 |

本轮在队友已有水墨界面基础上完成业务整合和操作调整，保留现有整体视觉风格。

### 2. 完善五角色和组织权限

统一系统管理员、创始人、部门老总、团队长和员工五种角色。

- 管理员负责账号和组织维护，业务人员通过 Android 使用日志和任务功能。
- 部门、团队的查看范围依据实际组织关系确定；创始人具有公司范围的业务查看权限。
- 领导只能向实际下级组织树中的较低级角色派发任务。
- 只有当前责任人可以反馈任务进展。
- 获得某人的查看权限，不代表可以修改其日志、反馈其任务或向其派发任务。

### 3. 落实日志编辑和上级查看申请规则

按照本轮采用的需求，完成或统一以下规则：

- 日志提交后仍可编辑，其他有权限的人刷新后看到最新内容。
- 按北京时间，允许编辑今天至七天前的日志，共八个日期；更早的日志保持可读。
- 下级可以申请查看直属上级，由上级审批。
- 申请通过后，只能查看获准范围内已提交的日志和任务，不包含草稿，也不获得修改权限。
- 支持拒绝和撤销查看授权；相关组织、角色或账号状态变化后，旧授权不能继续无条件使用。

“查看上级申请”已经实现，与尚未实现的工作请示、邀约是两个功能。

### 4. 改进任务派发和进度反馈

任务已支持名称、详细说明、优先级、责任人和截止时间，可以完成派发、接收、反馈和查看结果的完整流程。

本轮重点调整反馈方式：

| 原先操作 | 当前操作 |
| --- | --- |
| 输入 0—100 的完成百分比 | 选择“待开始／进行中／已完成” |
| 通过百分比推导任务状态 | 后端独立保存工作状态 |
| 显示完成数字和任务进度条 | 只显示工作状态和实际进度说明 |
| 难量化的工作也需要估算数字 | 用文字说明完成内容、遇到的问题和下一步 |

最终版本已删除百分比输入、数字展示和任务进度条，包括首页、任务列表与详情、日历和组织成员任务展示。进度说明仍为必填，最多 2000 字。

同时保留反馈草稿恢复机制，处理旧草稿中的百分比，避免更新后再次出现在界面或影响提交。

### 5. 优化截止时间与日历操作

任务截止时间改为系统日期、时间选择器，用户不用手动输入固定格式。支持不设置截止时间，也可以清除已有选择；选择过程中取消，不应覆盖原来的截止时间。

日历补充并接入月、周、日三种查看模式：

- 月视图：查看日期和选中日期的内容。
- 周视图：按周一至周日展示日志与到期任务，支持切换上一周、下一周。
- 日视图：集中查看当天日志与到期任务。

没有截止时间的任务继续保留在任务列表中，不人为生成日程日期。

### 6. 清理影响普通用户使用的入口和提示

按照实际使用场景，简化部分提示和操作：

- 隐藏普通用户不需要的开发登录入口。
- 隐藏尚不能提交的请示预览表单，避免出现“看得到但用不了”的功能。
- 移除日志编辑前固定返回成功的检查步骤，直接进入正常编辑流程。
- 保留真实登录鉴权、内容校验和失败提示。
- 调整任务、日志和首页文案，使提示更贴近用户要完成的工作。

### 7. 完成后端数据升级和版本交付

为支持独立工作状态，增加数据库迁移，将旧任务反馈转换为对应状态，同时保留原有任务数据。后端暂时保留旧客户端请求兼容，当前新版 App 已不收集百分比。

升级本地演示数据库前完成停服文件备份，升级后核对原有 **5 个账号、10 条日志、3 个任务**的原字段，确认未发生丢失或意外修改。

已完成新版 Android 安装包构建，当前版本为 **0.5.1-state-feedback，版本号 35**，可以使用相同签名覆盖安装。本地后端已恢复运行，可继续用于联调和演示。

安装包路径：`deliverables/Pandora-MVP-debug.apk`。

### 8. 同步需求和协作材料

更新需求说明、API 契约、Android 接口说明、待办、演示步骤、验收记录与 OpenSpec 规格，使文档与当前实现保持一致。
