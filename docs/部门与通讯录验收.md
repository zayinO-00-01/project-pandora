# 部门与通讯录验收

业务岗位固定为创始人、部门负责人、团队长、员工。直属上级关系按“创始人 → 部门负责人 → 团队长 → 员工”展示；Web 管理员是单独的系统账号，在组织架构页查看全公司汇报线，也可在账号管理中维护直属上级和部门名称。

| App 角色 | 通讯录可见范围 |
|---|---|
| 员工 | 自己的直属上级、本部门的其他员工 |
| 团队长 | 自己的直属上级、本部门的员工、其他部门或团队的团队长 |
| 部门负责人 | 全公司的有效业务联系人 |
| 创始人 | 全公司的有效业务联系人 |

通讯录的联系人可见性只影响联系方式和相关展示。查看日志和任务仍按实际下级及已批准的直属上级查看授权处理；跨部门联系人不会因此开放工作记录。任务责任人选择仍使用原有业务规则。通讯录不列本人、系统管理员和停用账号；没有部门的员工不会与其他未分配员工自动互见。

演示部门为综合管理部、技术研发部、市场销售部、运营服务部。迁移到 V29 后，可在 Web 账号管理手动设置部门名称，也可在本地通过管理接口运行 `python scripts/ConfigureDemoOrganization.py` 预览，再加 `--apply` 加入缺少的演示账号和部门名称。脚本保留现有账号的密码、角色、上下级和业务数据，不覆盖已配置的部门名称。

验收时用员工和团队长各登录一次，对比分组、直属上级、搜索结果及派发任务的候选名单。Web 新建或编辑账号时，填入合法身份证检查自动写入出生日期，再改错一位确认提示；紧急联系电话分别试填有效 11 位手机号、带区号座机、错误手机号及空值；未修改的旧资料不阻碍其他字段保存。
