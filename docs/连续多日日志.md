## 使用

写日志时点击日期，在四个可补录日期中分别选择开始日和结束日，点击「确认日期」，在下方填写一份统一说明并提交。例如 10 月 21 日至 23 日连续三天病假，只生成一条记录。

日期仍只能选今天及往前 3 天，不支持未来日期。历史或跨日记录直接提交后只读；单独今天的记录继续支持草稿和当天修改。草稿的起止日期及内容会一起恢复。

月历和周历用连续边框标明覆盖日期；点击任一天，下方显示整个起止区间、天数和完整说明。跨周时边框按各行延续，周视图中共享说明只显示一次，后续日期保留覆盖数量及指引。日志列表按起始日期归组并标注完整区间。原有单日日志正常保留。

年份选择按用户最新要求不作修改，交由队友处理。

## 后端升级

多日保存需要同时使用新版 API，不能只安装 APK。停止原本的本地演示服务后，在项目 backend 目录运行：

```powershell
java -jar ../deliverables/Pandora-0.5.11-log-ranges-api.jar
```

沿用现有数据库配置。Flyway V7 新增 end_date，把旧记录结束日期补为原日期；没有清空或删除历史数据。实际服务尚未替换或重启。若连接旧后端，安卓会提示更新并保留输入，避免结束日期被忽略。

接口 POST/PUT /api/v1/logs 新增可选 endDate，默认等于 logDate；响应返回 endDate。GET /logs?date=... 和面板今日记录查询覆盖该日的区间，权限继续由原接口控制。GET /logs/integrity 返回 supportsDateRanges=true。

开发直接进入后的视图中，附有明确属于本地预览的三天病假样例，便于不连接服务器时查看连框效果。

## 验证

Android 构建、35 项 JVM 测试通过；后端 57 项测试通过（含原有日志迁移、区间越界、历史不可修改、权限和日期覆盖）。后端包在独立目录构建，不覆盖运行中的服务。

原生联调用独立新版 Spring Boot 服务和专用 H2 数据库，未操作已有业务数据。截图位于 docs/原型/安卓控制台/多日日志-*.png。

原生验收通过：选择三天、重启进程后草稿恢复、真实 API 只保存一条起止日期记录；三个覆盖日都能看到共同说明；周视图共享详情去重、跨日历史只读、深色与 320dp 显示正常，日期选择器确认/取消按钮可见。

旧草稿日期过期时，选择器会落在当前允许补录窗口内，原正文保留，保存前仍重新校验起止日期。
