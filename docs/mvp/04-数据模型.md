# 首轮数据模型

首轮只实现 `users` 和 `work_logs`。旧产品文档中的任务、面板等表留给对应迭代，不提前创建无业务使用的整套表。

## users

| 字段 | MySQL 类型 | 约束与说明 |
|---|---|---|
| id | BIGINT | 正数、自增主键；API 输出字符串 |
| username | VARCHAR(64) | 非空、唯一；预置小写 ASCII 登录名 |
| password_hash | VARCHAR(255) | 非空，BCrypt 哈希；禁止通过 API 输出 |
| display_name | VARCHAR(64) | 非空，1–64 字符 |
| role | VARCHAR(16) | 非空，STAFF / LEADER / ADMIN |
| manager_id | BIGINT | 可空，外键到 users.id；首轮指向 LEADER，不得等于自己 |
| created_at | DATETIME(3) | 非空，以 UTC 保存 |

初始化程序检查角色、直属关系有效性和循环；数据库建立自引用外键，`ON DELETE RESTRICT`。role 使用数据库 CHECK 与应用枚举双重约束（选用支持 CHECK 的 MySQL 8.0.16+）。manager_id 建索引。

首轮不提供角色/直属关系编辑或用户删除接口；不允许注册时自行声明为领导或管理员。

## work_logs

| 字段 | MySQL 类型 | 约束与说明 |
|---|---|---|
| id | BIGINT | 正数、自增主键；API 输出字符串 |
| user_id | BIGINT | 非空，外键 users.id；从认证身份取得 |
| log_date | DATE | 非空，上海业务日期，不晚于当前业务日期 |
| content | TEXT | 非空，去首尾空白后 1–2000 Unicode 码点 |
| version | INT | 非空，初始 0；每次成功修改加 1 |
| created_at | DATETIME(3) | 非空，以 UTC 保存，创建后不变 |
| updated_at | DATETIME(3) | 非空，以 UTC 保存，修改时更新 |

采用 `(user_id, log_date, created_at, id)` 索引服务按作者/日期查询。允许同日多条，因此不创建 `(user_id, log_date)` 唯一约束。作者外键 `ON DELETE RESTRICT`。首轮不设 status 或软删除字段，不提供删除 API。

日志日期的“不得晚于今天”由应用校验，不能以固定数据库 CHECK 表达随时间变化的规则。数据库可校验 `CHAR_LENGTH(content)` 在 1–2000，空白处理仍由应用负责。Java 不能直接把 UTF-16 的 `String.length()` 当 Unicode 码点数量。

## 时间与并发

业务默认时区 `Asia/Shanghai`，由后端判定“今天”。数据库连接会话按 UTC，`DATETIME(3)` 字段按 UTC 读写；API 序列化带时区偏移。客户端不能自行改变作者或保存时间。

更新须采用等价于 `WHERE id=? AND user_id=? AND version=?` 的原子条件，并在同一事务内递增 version。若记录仍存在但版本不匹配，返回 409；不可写记录返回 403。不允许先读取版本、后无条件覆盖。

## Flyway 与测试数据

首个迁移建立两张表、索引与约束。已在共享环境执行过的迁移不原地修改，新增迁移修正；JPA 只校验结构，不通过自动 update 改表。

尚未建立数据库的情况下直接使用本文模型。若组员已按旧状态模型建库，需要新增迁移移除旧状态并保留已有正文；禁止未经确认删除现有数据。

演示初始化与结构迁移分开：由显式的 dev/demo profile 初始化账号，口令通过未提交的本地环境配置提供并哈希，不在文档或生产迁移里提供通用明文密码。

最少演示身份：领导甲、甲的两名直属员工、领导乙、乙的一名员工；可另加管理员验证其无默认全员日志权限。关联通过预置用户名解析，不依赖恰好自增到某个 id。上述账号仅为测试设计，当前尚未实际创建。

数据库重启验证使用独立测试库/演示库，记录操作前后的日志 id 和正文；不能通过清空数据库再装载样例数据伪装持久化成功。
