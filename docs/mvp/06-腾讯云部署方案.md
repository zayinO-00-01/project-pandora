# 腾讯云首轮部署方案

## 购买建议

推荐腾讯云轻量应用服务器：**2 核 CPU、4GB 内存、至少 60GB SSD、Ubuntu 24.04 LTS、3–5Mbps 带宽**。适用于五人开发、少量甲方试用、文字日志为主的首轮系统。这是初始容量建议，不是压测结论，不承诺并发人数。

若学生套餐的 4 核 8GB 价差很小，可选更大配置；当前不需要为微服务或模型推理购买高配。2GB 内存同时运行 Spring Boot 和 MySQL 余量较小，不建议。优先考虑短周期或合适的学生套餐，并核对月流量、续费价格和实际可选磁盘规格；本文件未查询腾讯云实时价格。

| 项目 | 首轮选择 | 原因 |
|---|---|---|
| 产品 | 轻量应用服务器，一台 | 网页静态资源、API、数据库集中部署，易维护 |
| 镜像 | Ubuntu 24.04 LTS，x86_64 | 用通用系统镜像，避免绑定额外建站面板 |
| 数据库 | 同机 MySQL 8.0 容器 | 小规模试用先控制成本，持久卷和备份必做 |
| Web 入口 | Nginx，同域名 `/` 与 `/api` | 减少跨域配置 |
| 构建 | 本地或 CI 构建后上传制品 | 避免构建和数据库争抢小服务器内存 |
| 可暂缓 | 云数据库、Redis、对象存储、负载均衡、Kubernetes | 首轮日志流程没有对应需求 |

地域优先选靠近团队和甲方的可用地域。中国大陆地域通过自有域名提供公网网站需要安排 ICP 备案，证书不等于备案；购买前核对腾讯云备案要求及实例资格。不要把“买完即可立刻通过域名上线”作为一周计划的前提。域名/备案未就绪时先用局域网演示；若考虑其他地域，应权衡延迟、预算与实际可用性。

## 运行拓扑与网络

浏览器 → Nginx 443 → 静态 Web / 内部 API 8080 → 内部 MySQL 3306。

- 安全组与主机防火墙：443 供试用；80 仅证书验证或 HTTPS 跳转；22 只允许团队维护来源 IP，必要时更新允许列表。
- 不向公网开放 8080、3306、13306、5173。生产 MySQL 不映射宿主机端口，维护通过 SSH 隧道等受控方式进行。
- Nginx 将 `/api/` 原样转给后端，保留前缀；其他前端路由回退到 `index.html`。缺失的 API 不回退为 HTML。
- 配置实际域名与可信证书，HTTP 跳转 HTTPS。生产环境不直接运行 Vite 开发服务器。

## 4GB 内存初始预算

| 组件 | 建议起点 |
|---|---|
| Java | 堆 `-Xms256m -Xmx768m`，进程总量另含元空间/线程/直接内存，容器预算约 1.25–1.5GB |
| MySQL | Buffer Pool 从 256MB 起，连接数按小规模设置，容器预算约 1GB |
| Nginx | 约 128MB 预算 |
| 系统、Docker、文件缓存与余量 | 剩余内存 |

上述值是调优起点，需运行后观察进程 RSS、数据库连接、磁盘和接口响应。持续 OOM 或高内存压力时先排查配置/泄漏，必要时升级；不要依赖频繁重启维持运行。

## 发布、备份与恢复

1. 部署负责人安装 Docker/Compose，提供不含密钥的配置样例；实际口令和 JWT 密钥保存在服务器受限配置中，不提交 Git。
2. 上传已构建 Web 与后端制品，以 Git 提交号标记版本。先备份数据库，再执行 Flyway 和启动服务。
3. MySQL 使用持久卷；日志限制单文件大小与轮转数量，避免磁盘被占满。
4. `/api/v1/health` 返回 200/UP 后，仍需执行登录、写入、查询、越权检查；健康检查不等于产品验收。
5. 每天备份数据库、保留最近 7 份，并定期复制到服务器以外的受控位置；首次演示前在独立测试库验证恢复。只留同一块云盘上的备份无法抵御整盘丢失。
6. 发布失败优先回滚到兼容现有表结构的上一个应用制品；Flyway 不自动逆向回滚。涉及破坏性结构变更时另行准备迁移/恢复方案，不能为了回滚应用随意覆盖已产生的用户数据。

首次可人工部署。自动构建和自动发布后续再加；未经实际部署，本文件中的域名、服务和账号均不是已存在资源。
