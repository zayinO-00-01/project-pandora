# 一周交付任务与验收

用户已确认：希望一周内提供可试用版本，首轮采用手机/电脑浏览器；一人擅长前端，两人擅长后端/服务器，两人可灵活安排。下列 A–E 是本轮职责代号，不擅自对应仓库 P1–P5 的实名，排入看板时填写姓名并同步成员映射。

| 代号 | 主责 | 开发与验证任务 |
|---|---|---|
| A 前端主责 | Web 工程、路由、公共样式、领导查询 | API 客户端、角色导航、下属筛选、手机/桌面布局与功能自测 |
| B 后端主责 | 日志业务与数据库 | Flyway 两表、增改查、分页、原子版本控制、业务单元与集成测试 |
| C 后端与部署 | 认证、组织关系、运行环境 | 登录/me/下属接口、权限协作、配置/容器/反代/健康检查、部署验证 |
| D 灵活成员一 | 员工日志页面 | 按 A 的公共组件规范实现列表、新建、编辑、详情及输入保留，与 B 联调 |
| E 灵活成员二 | 测试工具与交付验证 | 编写演示数据初始化、Playwright 核心流程用例；协助空状态与错误提示实现、整理反馈 |

全员对自己提交的 AI 生成代码做运行验证和人工审阅；生成文件不等于功能完成。B/C 先明确认证上下文与异常结构；A/D 先约定导航与共享 API 客户端，减少同时修改入口文件。

## 七天安排

Day 1 指实际开始开发的第一天，以下为团队目标，可按发现重估。课程 Sprint 编号仍按教学周期记录，一周计划是其中的小增量。

| 时间 | 主要工作 | 当天可检查的结果 |
|---|---|---|
| Day 1 | 规则与契约对齐；A 建 Web 壳，B 建数据层，C 建认证骨架与环境，D 建表单，E 准备用例 | Web 能打开，API/数据库能启动，契约与分工一致 |
| Day 2 | 登录、日志创建与个人查询接通真实后端 | I1：手机浏览器写日志，重新登录仍能读到；即可提前试用 |
| Day 3 | 领导直属下属筛选与日志详情 | I2：电脑浏览器看到手机录入的同一记录；越权拒绝 |
| Day 4 | 修改、版本冲突、无效输入、失败保留与分页 | I3：首轮功能齐全，必要异常有明确提示 |
| Day 5 | 集成验收与共享部署 | 手机/电脑完整流程通过，演示数据可复现 |
| Day 6 | 甲方亲自操作；修复阻断问题 | 真实反馈、缺陷清单和下一轮候选需求 |
| Day 7 | 复测、整理版本与证据、重排 Backlog | MVP 可运行，未解决问题和下一轮安排明确 |

不等 Day 6 才能展示。Day 2/3 有可运行增量即邀请试用；甲方无空时保留版本和演示记录，约最近可用时间，不伪造已评审结论。进度落后时优先保留登录→录入→落库→授权查看，减少视觉修饰和自动部署，不取消授权、真实持久化与必要验证。

## 验收用例

| 编号 | 操作 | 预期结果 |
|---|---|---|
| AC01 | 正确与错误口令登录 | 正确 200 并发 token；错误 401 不发 token |
| AC02 | 员工新建有效日志并重新登录查询 | 201，数据保留，列表与详情一致 |
| AC03 | 空白正文、超长正文、未来日期 | 400，无新记录，页面明确提示 |
| AC04 | 同一员工同日建两条日志 | 两条独立记录，排序稳定 |
| AC05 | 直属上级按员工/日期查详情 | 200，范围和正文正确 |
| AC06 | 员工查/改他人日志，其他团队领导查询 | 403，无正文泄露，无写入 |
| AC07 | 无 token 或过期 token 调业务接口 | 401，重新登录 |
| AC08 | 作者修改，上级刷新 | version 递增，双方看到最新正文 |
| AC09 | 两处读取同版本，先后保存 | 第一次成功，第二次 409；不覆盖新版本，本地输入保留 |
| AC10 | 后端不可达或保存超时 | 不误报成功，保留输入；超时先查记录再决定重试 |
| AC11 | 保存后重启 API 与数据库 | 同一条日志仍在，正文不变，使用持久化目录 |
| AC12 | 无日志/无下属、分页边界、无效页码 | 合法空列表 200，非法参数 400，不扩大数据范围 |
| AC13 | 管理员读取他人日志 | 首轮无额外权限，403 |
| AC14 | 不存在 id 与非法 id | 不存在 404，格式错误 400，错误结构一致 |
| AC15 | 数据库不可用时查 health | 503/DOWN，不泄露连接信息 |
| AC16 | 360px、390px 手机和 1366px 电脑操作 | 无整体横向溢出，筛选/正文/保存按钮可用 |

安全性证据重点为 AC01/06/07/13；可靠性为 AC02/09/10/11。每项记录前提、操作、预期、实际结果、版本、执行人和证据路径；目前均未执行。自动化优先覆盖一条真实端到端流程及后端权限/版本控制，布局可人工验证。

## 完成标准与演示

故事完成须同时满足：真实后端和 MySQL 可运行；正向与必要异常通过；非作者 PR 审阅；需求/API/OpenSpec/看板一致；无阻断主流程缺陷。公网部署或页面数量不替代验收。

五分钟演示：手机新建→电脑领导刷新看到→员工修改→领导看到更新→非直属账号拒绝访问→甲方亲自填写查询。网页刷新需重新登录是首轮已知限制，反馈后决定是否增加会话持久化。
