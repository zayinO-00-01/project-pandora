## 文档效力与已知条件

- 本目录与 `backend/openapi.yaml` 是首轮 MVP 的开发约定；产品初稿仍保留完整产品愿景，旧文件中的注册、面板、审批状态与部署安排不自动进入首轮。
- 原 `sprint-0-baseline` 是早期方案记录，本轮重叠能力按 `mvp-log-feedback` 开发；尚无已实现规格，不提前归档，不将任务标记为完成。
- 用户已确认首轮采用响应式 Web，目标一周内，老师未指定首轮必做内容；最终 Android 要求仍保留。这是团队交付安排，不代表甲方已认可所有产品细节。
- 团队能力为一名前端、两名后端/服务器、两名灵活成员；按职责分工，姓名自行对应。七天计划按开始开发当天记 Day 1，不把目标日期写成甲方承诺。
- 飞书看板尚待建立。本次只更新本地文档，不代表已在飞书创建卡片、已提交 Git、已有运行环境或公网地址。

## 本次解决的旧约定冲突

1. 日志修改、上级查询与 Web 日志查询移入首轮；任务查询仍在后续。
2. 采用保存成功后可见、作者可修改的规则，首轮删除草稿/提交/归档状态。
3. 增加直属上级关系，明确领导不能查看所有员工；管理员不因角色自动取得全员日志权限。
4. 补全日志详情、日志修改、当前用户和直属下属列表接口。
5. 先实现局域网真实联调；公网服务器、自动部署不再阻塞首次反馈。
6. 两项首轮非功能要求明确为安全性和可靠性，并附可执行验收场景。
