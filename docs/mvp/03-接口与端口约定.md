# 接口与端口约定

本文是计划中的运行约定，不代表这些端口当前已经有服务监听。API 结构以 [backend/openapi.yaml](../../backend/openapi.yaml) 为准。

## 默认端口

| 服务 | 开发默认端口 | 访问者及地址 | 说明 |
|---|---|---|---|
| Vite Web | 5173 | 本机 `http://localhost:5173`；局域网 `http://<开发机IP>:5173` | 配置 `strictPort: true`，被占用时明确报错，不悄悄换端口 |
| Spring Boot API | 8080 | `http://localhost:8080/api/v1` | Web 经 Vite 代理；Android 直接访问可达地址 |
| MySQL 本机服务/容器内 | 3306 | 后端访问 | 不向客户端或公网开放 |
| 容器映射到宿主机的 MySQL | 13306 | 本机后端访问 `127.0.0.1:13306` | 建议绑定 `127.0.0.1:13306:3306`，避开已有本机 MySQL |
| 对外 HTTPS 反向代理 | 443 | `https://<实际域名>` | 后续部署，Web 与 API 同源 |
| HTTP 重定向 | 80 | 后续部署时跳转 HTTPS | 非首轮必需 |

本机运行后端 + 本机 MySQL：`DB_HOST=127.0.0.1, DB_PORT=3306`。本机后端 + 容器 MySQL：端口为 `13306`。同一 Compose 网络内后端：`DB_HOST=mysql, DB_PORT=3306`，不能使用容器内的 `localhost` 指向另一容器。

端口冲突时优先调整本项目配置并同步文档，不关闭其他项目服务。局域网演示只为需要的端口添加限定范围的入站规则，不关闭整个防火墙。

## Web 首轮联调与后续 Android 接入

Web 默认请求 `/api/v1`；Vite 将 `/api` 原样代理到 `http://127.0.0.1:8080`，不删除 `/api` 前缀。浏览器收到的响应仍同源，首轮不需要开放任意来源 CORS。

| 客户端 | API Base URL |
|---|---|
| 本机接口调试工具 | `http://127.0.0.1:8080/api/v1/` |
| Android Studio 标准模拟器 | `http://10.0.2.2:8080/api/v1/` |
| 同一局域网 Android 真机 | `http://<开发机局域网IP>:8080/api/v1/` |
| 后续正式环境 | `https://<实际域名>/api/v1/` |

`10.0.2.2` 仅适用于标准 Android 模拟器。真机里的 `localhost` 指向手机自身，不是开发电脑。Retrofit Base URL 末尾保留 `/`，接口相对路径写 `logs` 等，不重复拼接 `/api/v1`。

局域网试用时 Vite 监听 `0.0.0.0:5173`，API 监听可被局域网访问的地址。确认设备同网段且网络不隔离客户端。若必须跨源访问，后端只允许明确列出的开发 Origin 和 `Authorization, Content-Type`，不直接放开任意 Origin。

## 最小 API 清单

| 方法 | 路径（前缀 `/api/v1`） | 目的 | 权限 |
|---|---|---|---|
| GET | `/health` | 检查进程与数据库可用性 | 无需登录，只返回 UP/DOWN |
| POST | `/auth/login` | 登录 | 无需登录 |
| GET | `/users/me` | 当前身份 | 已登录 |
| GET | `/users/me/subordinates` | 直属下属选项 | LEADER，仅直属；空列表合法 |
| GET | `/logs` | 分页日志列表 | 默认本人；指定 userId 须本人或直属下属 |
| POST | `/logs` | 创建本人日志 | 已登录 |
| GET | `/logs/{id}` | 读取日志详情 | 本人或有权限的直属上级 |
| PUT | `/logs/{id}` | 修改日期和正文 | 仅作者，必须提交版本号 |

示例：`GET /api/v1/logs?userId=101&date=2026-09-24&page=0&size=20`。页码从 0 开始，size 为 1–100，默认 20。顺序固定为 `logDate DESC, createdAt DESC, id DESC`。不传 userId 时只查本人；不会默认为全团队。

登录以外的业务请求带 `Authorization: Bearer <token>`。写请求为 `Content-Type: application/json`。ID 对外使用十进制字符串，避免 JavaScript 精度丢失。

创建请求示例：

```json
{"logDate":"2026-09-24","content":"完成登录接口联调，记录一处错误提示问题。"}
```

成功返回 HTTP 201 与完整日志；作者由 token 对应用户确定。修改请求增加 `version`，使用 GET 返回的值；成功返回 HTTP 200 与新版本。日期响应为 `YYYY-MM-DD`；时间戳使用带时区的 ISO 8601，例如 `2026-09-24T10:00:00+08:00`。

错误示例：

```json
{"code":"VERSION_CONFLICT","message":"日志已被更新，请重新读取后再保存","requestId":"example-request-id"}
```

固定业务码：`VALIDATION_ERROR`、`AUTH_REQUIRED`、`INVALID_CREDENTIALS`、`FORBIDDEN`、`NOT_FOUND`、`VERSION_CONFLICT`、`INTERNAL_ERROR`。客户端根据状态码/业务码处理，不依赖中文提示文本判断逻辑。

## 联调顺序

1. 启动 MySQL 并执行 Flyway；加载仅演示环境可用的账号数据。
2. 启动 API，`GET /health` 返回 200/UP；数据库不可用时返回 503/DOWN。
3. 调登录接口并用 token 创建、读取日志，确认真实落库。
4. 手机浏览器和电脑浏览器均打开 Web 地址，统一经代理访问 API；本轮无需手机直接访问 8080。表中的 Android 地址供后续接入使用。
5. 更换角色和团队账号验证 401、403、空列表、保存失败、版本冲突。

目前仓库尚无可启动业务工程。具体 Maven/Gradle/npm 启动命令在工程创建且运行验证后补入各端 README，不将未验证命令写成已经可用。
