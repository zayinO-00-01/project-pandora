# 月历验证记录

本机 Windows、Java 21、H2 MySQL 模式。使用 MockMvc 在同一应用进程内串行请求，构造属于同一账号的虚构任务。每个接口先预热一次，下面是随后三次请求耗时的中位数和未压缩响应体字节数。旧列调用一期沿用的 `/tasks`；新版列分别请求 35 天摘要和所选日期的第一页。这些数据只反映接口，不含手机渲染和网络传输。

| 任务量 | 旧全量列表 | 新日期摘要 | 新当天第一页 |
| --- | ---: | ---: | ---: |
| 100 条，同一天 | 8 ms / 60,823 B | 4 ms / 286 B | 8 ms / 19,506 B |
| 1,000 条，同一天 | 48 ms / 609,424 B | 18 ms / 287 B | 22 ms / 19,507 B |
| 10,000 条，同一天 | 387 ms / 6,113,424 B | 122 ms / 290 B | 186 ms / 19,538 B |
| 10,000 条，分散在 35 天 | 381 ms / 6,122,223 B | 222 ms / 10,218 B | 349 ms / 19,614 B |

单日一万条时，打开月历的摘要和当天第一页共约 20 KB，原全量接口约 6.1 MB。接口耗时按各自请求记录；不将两项直接相加作为手机首屏时间。

在 `backend/` 可运行 `mvn -Dtest=TaskCalendarTests -Dpandora.calendar.benchmark=true test` 复测。后端含性能样本共 309 项通过；Android 116 项单测及 Debug APK 构建通过。Android 单测验证分页和溢出数字，未连真机验证手势或耗时。

另在临时 MySQL 9.6 实例上执行数据库迁移和月历接口功能测试：3 项通过，性能样本未启用。部署配置使用 MySQL 8.0，此处未在该版本上跑性能测试。
