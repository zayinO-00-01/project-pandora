## Context
Spring Boot 3 与两张现有表已可保存日志；Web 尚无工程。用户要求完成本地可演示增量，Android 暂空，减少重复验证。
## Goals / Non-Goals
完成日志草稿/提交/修改、授权成员选择及 Web 查看。暂不开发 Android、任务派发、完整日历和云部署。
## Decisions
- 后端沿用现有实体；新建 status 可省略（默认 submitted），PUT 更新正文/日期，POST /logs/{id}/submit 提交，提交后仍可编辑但不得撤回为草稿。
- 作者可见自己的草稿；管理者只看权限内他人 submitted 日志。LEADER 沿用 main 的直属下属范围，ADMIN 查看公司范围。GET /users 返回本人及权限内成员的公开字段。
- Web 使用 Vue 3/Vite；米白、深绿与少量橙色的清楚工作台，登录、团队日志、本人日志编辑。员工身份不能进入管理工作台。
- 相对 /api/v1 与 Vite 代理避免硬编码主机；本地启动构建 Web 到后端 static 并启动一个服务，默认 8080。浏览器同源与手机访问同一后端。
- H2 文件库用于本地，数据库数据保留；测试使用 H2 内存库。脚本可配置端口。
## Risks / Trade-offs
Android 未接入 → 提供员工演示脚本，不宣称移动端完成。首次需要 Java/Node 和依赖下载 → 缓存放 .tools，启动器检测工具并提示。
## Validation
一次基线、一次新增测试预期失败、实现后一次后端测试/前端构建；浏览器验收一次。后续仅针对失败修正重跑。手机及界面体验由用户手测。
