# 技术设计

本 change 的技术设计由以下文档共同定义，避免复制多份产生漂移：

- `docs/mvp/01-MVP范围与业务规则.md`：范围、页面、角色规则、反馈。
- `docs/mvp/02-技术架构与开发约定.md`：Vue/Java/MySQL、模块、认证和错误。
- `docs/mvp/03-接口与端口约定.md` 与 `backend/openapi.yaml`：运行地址与 API。
- `docs/mvp/04-数据模型.md`：用户、直属关系、日志、版本、日期和持久化。
- `docs/mvp/05-交付任务与验收.md`：七天增量与验收。
- `docs/mvp/06-腾讯云部署方案.md`：单机 Compose/Nginx、网络、备份和恢复。

前端只访问 API；后端集中检查用户身份、直属关系、写入作者及版本。首次在浏览器验证，未来 Android 使用同一 API，不为每个端复制业务服务。首轮无需 Redis、消息队列、微服务或 WebSocket。

已知取舍：仅预置账号、无刷新 token、网页刷新需重登录；仅直属查询；日志同日可多条；公开试用依赖 HTTPS/域名及部署条件。根据甲方实际反馈提出新的 change，不静默修改本轮规则。
